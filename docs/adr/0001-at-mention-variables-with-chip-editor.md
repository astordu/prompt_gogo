# 采用 @mention 风格的变量语法与 chip 编辑器

模板占位符从 mustache 风格 `{{select_content}}` 切换为 @mention 风格 `@select_content`，并将模板编辑器从纯 textarea 升级为 contenteditable + 原子化 chip 的方案。旧语法在应用启动时一次性自动迁移，之后不再识别。

## Considered Options

- **保留 `{{select_content}}` 语法**：无迁移成本，但双花括号对非技术用户不友好，且无法提供"整体选中/整体删除"的编辑体验——用户容易只删掉一半导致模板失效。
- **`@` 触发 + 转义机制（`@@`）**：为字面 `@` 提供转义。被否决：增加认知负担，而"过滤即退出"模式（Slack/Notion 心智模型）已自然解决字面 `@` 的问题——匹配不到候选时文本自动保留为普通字符。
- **TipTap/ProseMirror 编辑器框架**：内置 Mention 节点，功能完备。被否决：项目无构建系统（设置页直接 CDN 加载），为弹窗中的单字段编辑器引入重框架得不偿失。
- **保留 textarea + 键盘拦截模拟原子删除**：改动最小。被否决：无法提供视觉上的 chip 反馈，用户无法"看到"token 是一个整体。

## Consequences

- 存储语法变更不可逆：迁移执行后用户数据中不再存在旧语法，回退版本会导致占位符失效。
- 编辑器需自行处理 contenteditable 的序列化（DOM → 纯文本）、粘贴识别和撤销，但模板内容本质是"纯文本 + 少量 chip"，复杂度可控。
- 词边界识别规则（token 后紧跟字母/数字不匹配）意味着 `@select_contentX` 不会被识别为变量——这是刻意的保守取舍。
